# ASCN.AI Voice

Отдельная админка голосовых AI-агентов на Yandex AI Studio и OpenAI Realtime. Это самостоятельный проект: в нём нет Telegram, WhatsApp, рассылок и автоцепочек.

Интерфейс работает на **Nuxt 4 + Vue 3**. Существующий Next.js-сервис оставлен
как внутренний backend/API, чтобы не менять проверенную телефонию, авторизацию и
контракты данных. В Docker наружу публикуется только Nuxt; запросы `/api/**`
прозрачно передаются внутреннему backend-контейнеру.

## Что входит

- Yandex Speech Realtime и OpenAI GPT Realtime в одном конструкторе;
- естественный speech-to-speech диалог, server VAD и перебивание ответа;
- системный промпт, переменные, голос, язык и параметры конца фразы;
- память контакта и расшифровки звонков в ASCN;
- инструменты ASCN, MCP-серверы и пользовательские webhook-функции;
- Yandex Web Search и File Search для Yandex-агентов;
- тестирование голосом и текстом из браузера;
- исходящие звонки по API с переменными на конкретный звонок;
- тональный набор для прохождения автоответчиков и IVR;
- разбор звонка после завершения: итог, номер подтверждения, имя сотрудника, следующий шаг;
- фоновый звук, лимит длительности и тонкая настройка перебиваний;
- несколько обычных номеров `+7` или других стран через SIP;
- явная маршрутизация `номер / DID → голосовой агент`;
- перевод звонка живому оператору;
- Asterisk и ASCN Voice Gateway в Docker Compose.

## Поддерживаемые Realtime-модели

В конструкторе четыре провайдера: Yandex AI Studio, DeepSeek, OpenAI и xAI.

Yandex AI Studio:

- `speech-realtime-260528` — основная версия;
- `speech-realtime-250923` — предыдущая стабильная версия.

DeepSeek:

- `speech-realtime-deepseek-v4-flash` — экспериментальная версия, ответ может быть медленнее.

xAI:

- `grok-voice-think-fast-2.0` — единственная realtime-модель xAI, начинает отвечать примерно через 0,7 секунды.

xAI игнорирует параметр модели в адресе: `grok-voice-latest`, `grok-voice-1.0` и любое другое имя отдают ту же `grok-voice-think-fast-2.0`, поэтому в конструкторе она одна. Поле `output_audio_format` xAI тоже принимает и игнорирует — аудио всегда приходит как PCM 16 бит 24 кГц, ресемплинг для телефонии делает шлюз. Имя голоса не валидируется: при опечатке сервер молча возьмёт свой `xai_ara`, поэтому голос у xAI вводится текстом, а не выбирается из списка.

DeepSeek выбирается отдельным провайдером, но сама модель размещена в Yandex AI Studio: используются ключ и идентификатор каталога Yandex, отдельного ключа DeepSeek не нужно. Настройки синтеза (голос, амплуа, скорость) и распознавания у DeepSeek те же, что у Yandex.

OpenAI:

- `gpt-realtime-2.1` — флагманская Realtime-модель;
- `gpt-realtime-2.1-mini` — более быстрая и экономичная;
- `gpt-realtime-2`;
- `gpt-realtime-1.5`.

`gpt-realtime-translate` не включена в обычного агента: это специализированный переводчик без function calling. `gpt-realtime-whisper` — только распознавание речи, она не генерирует голосовой ответ. Устаревшие `gpt-realtime`, `gpt-realtime-mini` и GPT-4o Realtime намеренно не добавлены.

## Архитектура звонка

```text
телефонный номер / DID
        ↓
SIP-оператор
        ↓
Asterisk (регистрация SIP и RTP)
        ↓  AudioSocket PCM 8 kHz
ASCN Voice Gateway
        ├─ PJSIP endpoint → connection → tenant; DID только перепроверяется
        ├─ ASCN CRM-память и инструменты
        ├─ Yandex Realtime
        └─ OpenAI Realtime (PCM 24 kHz, ресемплинг в шлюзе)
        ↓
голосовой ответ абоненту
```

Yandex AI Studio и OpenAI API не выдают обычный телефонный номер. Номер приобретается у оператора, который предоставляет SIP server/registrar, login и password. Эти данные вводятся в админке; конфигурация Asterisk создаётся автоматически.

## Где подключить номер

- [SIPNET — регистрация и SIP ID](https://www.sipnet.ru/register)
- [MANGO OFFICE — виртуальный номер](https://www.mango-office.ru/products/virtual_number/)
- [Телфин — SIP-номер](https://www.telphin.ru/products/virtual-numbers/sip-number)
- [Zadarma — телефонные номера](https://zadarma.com/ru/tariffs/numbers/)

Можно использовать другого оператора, если он выдаёт SIP-регистрацию или SIP-trunk. Доступность номеров `+7`, требования к документам и регистрация номера определяются оператором связи.

## Первый запуск

```bash
node scripts/generate-deployment-env.mjs .env IP-СЕРВЕРА 3000
# Команда создаёт .env mode 0600 и один раз печатает пароль администратора.
docker compose up -d --build
```

Для разработки frontend отдельно: `npm ci --prefix frontend --legacy-peer-deps`,
затем `NUXT_BACKEND_URL=http://127.0.0.1:3000 npm run frontend:dev`. Backend в
это время запускается обычной командой `npm run dev`.

Compose намеренно не содержит секретов по умолчанию и не стартует с короткими
или совпадающими internal keys. PostgreSQL, Redis и MinIO используют разные
runtime-учётные записи; root/superuser credentials приложению не передаются.

По умолчанию панель слушает только `127.0.0.1`. Сначала настройте HTTPS reverse
proxy, который **перезаписывает** `X-Forwarded-For` и `X-Forwarded-Proto`, затем
явно включите `TRUST_PROXY=true`. Для локальной проверки используйте SSH tunnel.
Откройте HTTPS-адрес панели:

1. Создайте голосового агента и выберите Yandex или OpenAI.
2. В разделе «Подключение и номера» сохраните ключ соответствующего AI-провайдера.
3. Купите номер у SIP-оператора.
4. Добавьте номер, SIP server, login и password.
5. Выберите в поле «Какой агент отвечает» нужного агента.
6. Сохраните подключения — Asterisk перечитает созданные SIP-транки.

Для Yandex сервисному аккаунту нужна роль `ai.models.user` и scope `yc.ai.foundationModels.execute`. Для OpenAI создайте API key и, если ключ ограничен проектом, укажите Project ID. Для xAI создайте ключ в [console.x.ai](https://console.x.ai/home) и дайте ему доступ к эндпоинту voice.

Агенты, настройки, контакты, сессии и звонки хранятся в PostgreSQL; записи — в
tenant-scoped object storage. Legacy volume доступен только одноразовым migration
jobs; runtime-приложение его не монтирует. После успешной миграции persistent
markers делают последующие старты дешёвыми. Секретные поля не возвращаются в браузер.

## Исходящие звонки

Панель умеет звонить сама — через тот же Asterisk и тот же SIP-номер.

```bash
curl -s -X POST http://IP-СЕРВЕРА:3000/api/voice/calls \
  -H "authorization: Bearer $EXTERNAL_CALL_API_KEY" \
  -H "content-type: application/json" \
  -d '{"toNumber":"+79001234567","variables":{"caller_name":"Клиника на Ленина","caller_purpose":"Перенести приём с четверга на пятницу после 17:00 и узнать номер записи"}}'
```

Переменные звонка подставляются в промпт вместо `{{caller_name}}` и `{{caller_purpose}}` — так один агент обслуживает любые поручения. Статус и расшифровка: `GET /api/voice/calls/<id>`. Те же поля доступны из кабинета кнопкой «Позвонить» на вкладке «Звонки».

Из Claude Code звонок ставится скиллом `.claude/skills/ascn-call/SKILL.md` — он ищет номер в Контактах macOS или в интернете, спрашивает подтверждение и следит за звонком до итога. Чтобы скилл работал из любой папки, скопируйте его в `~/.claude/skills/ascn-call/`.

Оба маршрута — API и скилл — авторизуются отдельным
`EXTERNAL_CALL_API_KEY`. Он даёт право только на API звонков default tenant и
не открывает настройки, runtime или данные других тенантов.

## SIPNET

Для SIPNET в разделе «Подключение и номера» выберите оператора «SIPNET» — формат набора и регистрация подставятся сами:

- **SIP server** — `sipnet.ru`, общий хост для всех аккаунтов;
- **SIP login** — SIP ID из кабинета SIPNET;
- **Регистрация от** — SIP-логина: SIPNET регистрирует по SIP ID, а не по номеру;
- **Формат набора** — `7XXXXXXXXXX`, международный формат без плюса и без восьмёрки;
- **Транспорт** — UDP.

Входящие звонки приходят на SIP ID, если у вас не подключён прямой номер. В этом случае в поле «Номер телефона / DID» укажите сам SIP ID — по нему кабинет маршрутизирует звонок на нужного агента. Если прямой номер `+7` куплен отдельно, укажите его.

Что уточнить в SIPNET до продакшна: сколько одновременных SIP-сессий разрешено на аккаунт (один канал — один звонок за раз) и разрешена ли регистрация с IP вашего сервера. Прямой входящий номер у SIPNET — отдельная платная услуга, звонки без него будут только исходящими.

## Инструменты и skills

Встроенные действия ASCN работают сразу: чтение контекста, изменение контакта, этап воронки, заметки, тональный набор, перевод и завершение звонка. Любой внешний инструмент или skill подключается к агенту как HTTPS MCP-сервер либо как function/webhook с JSON Schema. Секрет Authorization хранится только на сервере.

## HTTPS и тест из браузера

Телефонные звонки работают через внутренний gateway. Для теста с микрофоном браузеру нужен публичный WSS-адрес. Направьте путь `/voice-ws/` вашего HTTPS-домена на `voice-gateway:8787`, сохраняя WebSocket Upgrade, и укажите полный адрес:

```text
wss://voice.example.ru/voice-ws/session
```

Тестовые сессии защищены короткоживущей подписью, которую выдаёт авторизованный кабинет.

## Порты

- `3000/tcp` — Nuxt-админка; backend доступен только внутри Compose как `app:3000`;
- `8787/tcp` — browser voice gateway, публиковать только через HTTPS/WSS reverse proxy;
- `5060/udp,tcp` — SIP;
- `10000-10100/udp` — RTP.

Перед публикацией заполните все обязательные значения из `.env.example`,
настройте HTTPS и off-site backup по
[`docs/BACKUP_AND_RESTORE.md`](docs/BACKUP_AND_RESTORE.md). Не удаляйте volumes
PostgreSQL, MinIO и legacy: последний нужен для контролируемого отката миграции.
